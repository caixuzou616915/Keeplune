# Keeplune

私藏 · Keeplune，一款基于 Flutter 的离线加密个人资料柜，用于集中保存证件信息和重要文件。

无需注册，无服务器，无统计埋点。资料和附件在本机加密保存，不提供自动云同步。

## 功能概览

| 功能 | 说明 |
| --- | --- |
| 证件管理 | 保存名称、持有人、证件类型、号码、分类、标签、备注及有效期 |
| 重要文件 | 保存文件资料、分类、标签、备注及附件 |
| 搜索与筛选 | 按资料信息搜索，按分类筛选；不识别图片文字或检索 PDF 正文 |
| 附件与预览 | 导入 JPG、PNG、PDF，支持图片缩放和 PDF 本地预览，单个附件最大 32 MB |
| 有效期管理 | 支持未设置、长期有效和指定日期，并在到期事项中按日期查看 |
| 本地提醒 | 可在到期前 30 天、7 天及当天上午 9 点提醒，不在通知中包含资料名称或号码 |
| 敏感信息遮挡 | 证件号码默认隐藏，主动显示后 15 秒自动隐藏 |
| 自动锁定 | 可设置闲置 1、2、5、10 分钟后锁定；进入后台、最小化或锁定会话时锁定，切换窗口时遮挡画面 |
| 密码与恢复 | 支持修改资料库密码，以及使用恢复密钥重设密码 |
| 加密备份 | 导出包含附件的 `.ovault` 备份，用于备份或迁移，最大 256 MB |
| 删除资料 | 支持删除单条资料，或验证密码后删除本机资料库 |

## 首次使用

1. 启动应用，创建资料库并设置 12 至 256 个字符的密码，建议使用较长且独立的口令。
2. 将应用生成的恢复密钥离线保存，并确认已经妥善记录。恢复密钥为 8 组、每组 8 位的十六进制字符，请勿与备份放在同一处。
3. 添加证件或重要文件，填写分类、标签等信息，按需导入附件。
4. 为有到期日期的资料启用提醒，并在设置中允许本地提醒及系统通知权限。
5. 定期导出加密备份，保存在可靠位置，并保留对应的密码或恢复密钥。

## 安全与隐私

- **本地加密**：使用 AES-256-GCM 进行认证加密，密码通过 Argon2id 派生密钥，并使用 HKDF-SHA256 派生用途子密钥。实现见 [lib/core/crypto.dart](lib/core/crypto.dart)。
- **离线策略**：应用对 Dart HTTP 客户端设置离线访问限制，PDF 预览不加载远程内容。没有账号、后端服务或自动同步功能。
- **恢复凭证**：忘记密码后可使用恢复密钥重设密码；密码与恢复密钥均丢失时，无法恢复加密资料。恢复密钥应视为与密码同等敏感的凭证。
- **本机保存位置**：Windows 使用 `%LOCALAPPDATA%\OfflineVault\vault\`；Android 和 iOS 使用应用支持目录下的 `vault` 子目录。
- **原文件仍然存在**：导入只会把附件加密保存到资料库，不会删除外部原文件，请自行管理原文件及其备份。
- **系统文件选择器**：应用本身不上传资料，但系统选择器可能提供云盘位置，选择云盘可能由系统下载或上传文件。需要完全本地保存时，请选择本地目录。
- **设备安全边界**：本地加密不替代设备安全。请妥善管理设备、屏幕共享和系统权限；窗口保护不可用时，应留意应用提示。

## 备份与恢复

在设置中导出加密备份，恢复时选择 `.ovault` 文件，并输入**导出该备份时的密码或恢复密钥**。

> 恢复会整体替换当前资料库，不支持合并。恢复前请先备份现有资料。

- 备份包含资料信息和附件，导出及恢复时会校验附件。
- 修改当前资料库密码不会更新已经导出的备份，旧备份仍使用导出时的密码；恢复密钥不因修改密码而改变。
- 删除本机资料库不会删除已经导出的备份，也不会删除导入前的原文件。
- 应用不会自动同步或替你保管备份。删除应用或清理应用数据前，请先确认备份及恢复凭证可用。

## 提醒限制

提醒由系统本地通知调度，不依赖服务器。同一天的提醒合并，每次解锁时更新最近 60 个提醒日期。

系统通知权限、省电策略、长期未打开应用或时区变化都可能影响提醒送达；Android 使用非精确调度，不能保证准点通知。重要事项请定期在应用中核对，不应只依赖通知。

## 开发与运行

当前版本为 `0.1.0+1`，Dart 包名为 `offline_vault`。依赖与 SDK 约束见 [pubspec.yaml](pubspec.yaml)。

### 环境要求

- Flutter SDK，其内置 Dart SDK 需满足 `^3.13.7`，即 `>=3.13.7 <4.0.0`。
- Android：配置 Android SDK、JDK 及模拟器或设备。
- Windows：安装 Visual Studio 的“使用 C++ 的桌面开发”工作负载及 Windows SDK。
- iOS：需要 macOS、Xcode 和相应的签名配置。

仓库包含 Android、iOS、Windows 工程；不包含 Web、macOS 或 Linux 工程。各平台的通知、文件选择和系统保护能力需在对应设备上验证。

### 获取依赖并启动

```sh
flutter doctor
flutter pub get
flutter devices
flutter run -d <device-id>
```

将 `<device-id>` 替换为 `flutter devices` 列出的设备标识。例如，在 Windows 上运行：

```sh
flutter run -d windows
```

### 构建

在具备相应平台工具链的主机上执行所需命令：

```sh
flutter build apk --release
flutter build windows --release
flutter build ipa --release
```

Windows 构建需在 Windows 上执行，iOS 构建需在 macOS 上执行。发布前还需配置并验证对应平台的签名与打包设置。

### 检查与测试

```sh
flutter analyze
flutter test
```

现有 [test/](test/) 覆盖资料库、模型与提醒日期、文件访问策略及应用界面等逻辑。仓库还提供 Windows PowerShell 核心验证脚本：

```powershell
.\tool\test_core.ps1 -FlutterRoot "C:\path\to\flutter"
```

[tool/test_core.ps1](tool/test_core.ps1) 会在临时目录解析排除 `pdfrx` 的测试依赖图，运行仓库中的测试源码，不修改项目源码。该验证不覆盖原生 PDF 渲染和平台通道；本地通知、系统文件选择及窗口保护仍需设备测试。
